## Porting plan for (a)

1. **Tool-argument typing** (serve/frontend.py; no engine change, no dan-99 file).
   - Add `_declared_type(schema)`: "string" when `type == "string"`, or `"string" in type` (list), or any `anyOf`/`oneOf`
     member resolves to string (recursive); else the plain `type` string, else None. Maya gates it on GLM (`unions=`);
     for us apply it always (a schema that admits a string keeps the text as written; that is what the client declared).
   - Use it at the three places that read the declared type today: `parse_tool_call` line ~1183
     (`coerce_value(value, (props.get(pname) or {}).get("type"), notes)`), `OutputParser` `self.sdeclared = {...}` ~1537,
     and the streamed path (~1554/1601 read `sdeclared`). Today `coerce_value` returns `value` for declared "string" only;
     a `["string","null"]` or `anyOf[string,...]` parameter falls to `json.loads`, so `"123"` -> 123, `"true"` -> True.
   - In `coerce_value`, after `json.loads` fails: if `declared in ("boolean", "null")` (or a list containing them) map
     `true/false/none/null` case-insensitively to True/False/None (StrataFast: "JSON is still tried first"). Today
     `<parameter=x>False</parameter>` on a boolean goes out as the string "False" and zod rejects it.
   - Tests: add cases to serve/test_tolerant_tool_calls.py (whole body and streamed, both parsers); StrataFast's
     tests/server/tool_args_test.cpp lists the cases.
   - Conflicts: none expected; serve/frontend.py was last touched by the Maya robustness port. dsml.py (DeepSeek) untouched.

   basalt: `open()` that passes `file.open` but fails the "table extends past the end" check calls `close()` with the file
   open, an empty `free_slots` and the previous session's `max_inflight` -> `file.wait(c, 64, -1)` blocks forever. Exact.
   Test: ple_reader_test - open OK, close, reopen with a too-large n_rows, expect a clean error.

## Porting plan for (b)

4. **Quarter-size tail tasks** (dan-99). pool.cpp `drain()` modes 5/6/7 compute `g0 = R*j/T, g1 = R*(j+1)/T`. Replace with
   basalt's `part_row(j, T, R)`: `small = min(threads, T/2)`, `big = T - small`, `units = 4*min(j,big) + max(0, j-big)`,
   row = `R*units/(4*big + small)`. Also for `fgu_tasks_`/down split under mode 7, and the NUMA slice path (`ns.rows/tasks`).
   Exact: each row's dot is computed alone; the WindowInvariant arithmetic is per row. A/B: one GPU session, edit + short
   windows, `pool trace` idle-at-end per thread; build only if CPU-expert ms drops >= 0.3 ms on the edit window. Note pancake
   cuts 3 tasks per thread (phase_tasks) vs basalt's 8-12, so the tail is a larger share here - the change may pay more, or
   T could rise instead (already swept: "CPU pool settings sweep - defaults best").

   -> first `_mm_prefetch(..., _MM_HINT_T1)` this task's down rows (`mjobs_[e].blob + nfmt->down_off + r0*d_row`, `(r1-r0)*d_row`
   bytes), checking `fready_` every 4 KB. Only matters if item 29 (FUSE_PHASES) becomes default; bundle it into item 29's A/B.
6. **SpinWait in the MTP draft wait**. src/core/mtp.cpp ~1868 and ~1905 spin on `h_out_[j] < 0` with `strata_cpu_pause()`
   and a `cudaStreamQuery` every 1024 spins - identical to basalt's draft.cpp before #246. Add a small SpinWait helper
