# Strata with LAN GPU workers

**Use graphics cards in other Linux PCs to help your main PC run DeepSeek V4.1 Flash.**

We extended Strata so an RTX 5090 can share part of the model's work with older GPUs
over the local network. Our selected setup uses **two RTX 2080 Ti workers and one
GTX 1070 worker**, all on gigabit Ethernet. They help generate the same answer;
they are not running three separate chatbots.

## Why we built this

Our RTX 5090 has 32 GB of GPU memory. The DeepSeek model files we use are about
274 GB, so the whole model cannot fit on that card. Strata already makes it
possible to run the model by using system RAM and the SSD as well as the GPU.
Work that stays outside GPU memory still depends on the main PC's CPU, RAM and
storage.

We also had older graphics cards in other PCs. We wanted to use their GPU memory
and computing power to help the 5090. The original DeepSeek engine could not send
this work to GPUs in separate PCs, so we added that connection.

## What we changed

DeepSeek divides some of its work into parts called **experts**. Our extension
lets other PCs store and run selected experts:

1. **The 5090 PC stays in charge.** It manages the conversation, chooses the experts
   needed for each step, and produces the final answer through the same local API.
2. **Each worker keeps a different set of expert weights in GPU memory.** These
   weights are loaded when the server starts. The worker does not need its own
   copy of the full 274 GB model.
3. **During generation, only small inputs and results travel over SSH.** We do not
   send model weights across the network for every generated token.
4. **The main PC and workers calculate their parts at the same time.** Moving some
   experts to the workers also leaves more room in the main PC's RAM cache for
   other experts.
5. **If a worker disconnects, the main PC does its missing work locally.** We tested
   this by stopping a worker during an answer and checking that generation finished.

The setup still uses the **same 2.25-bit weights, all six selected experts per
step, and a 64K context window**. The gain comes from sharing the work, not from
skipping experts or switching to a smaller model.

## Our working setup

| Role | Graphics card | GPU memory | Connection |
| --- | --- | ---: | --- |
| Main PC | RTX 5090 | 32 GB | Runs the main engine and API |
| Worker 1 | RTX 2080 Ti | 11 GB | Gigabit Ethernet over SSH |
| Worker 2 | RTX 2080 Ti | 11 GB | Gigabit Ethernet over SSH |
| Worker 3 | GTX 1070 | 8 GB | Gigabit Ethernet over SSH |

That is **one main GPU plus three remote GPUs**. The main PC has 64 GB of system
RAM. The remote PCs need the worker program and its CUDA runtime, not a full
Strata model installation. The existing API and client connections can stay the same.

## What improved

We compared the setups using the same prompts and response lengths within each
test. These numbers measure answer generation speed, in tokens per second.

- **Adding the two RTX 2080 Ti workers:** the 5090-only setup measured **9.21
  tokens/sec**, and the setup with two workers measured **10.21 tokens/sec** —
  about **11% faster**.
- **Adding the gigabit GTX 1070 as a third worker:** in the next comparison, two
  workers measured **9.75 tokens/sec**, and three measured **10.05 tokens/sec** —
  another **3.1% improvement**. All six responses were faster with the third worker.

**The three-worker setup gave the best generation speed in the latest comparison,
so that is the setup we selected.** It puts older GPUs to useful work while keeping
the same model and context size on the main PC.

These were two separate comparisons, not one continuous benchmark. Each setup
generated 1,152 tokens across six short responses with reasoning disabled and
64K configured context. Compare the before-and-after numbers within each bullet;
the full measurements are in the [two-worker report](docs/LAN_EXPERTS_RESULTS.md)
and [three-worker report](docs/LAN_EXPERTS_GTX1070_RESULTS.md).

We also tried a fourth worker, but that PC's connection on **our network** was only
100 Mb/s, not gigabit. We left it out of the selected setup. That run was not a
test of four workers on gigabit links; the network details are in the report above.

## Try the LAN version

This fork is based on **Strata v0.2.8**. The LAN workers have been built and tested
on **Linux with NVIDIA CUDA**, including the RTX 2080 Ti and GTX 1070.

Start with the **[LAN build and setup guide](docs/LAN_EXPERTS.md)**. It explains how
to build the main engine and workers, add your own SSH hosts, and start the server.
The ordinary Strata installers shown below do not include this added LAN code;
use this branch and the LAN guide for the multi-PC setup.

## Install

<a id="option-a-the-strata-app"></a>

### Desktop app

**[Download Strata for Windows, Linux or Mac →](https://github.com/Niko1221/Strata/releases/latest)**

Install the app, choose a model, and start chatting. There is one installer for each system. On first start the app
downloads the engine for your graphics card. [Help with the installer](docs/INSTALL.md#the-app).

<sub>Files: `Strata-0.2.8-windows-x64-setup.exe` · `Strata-0.2.8-linux-x86_64.AppImage` · `Strata-0.2.8-macos-arm64.dmg`</sub>

### Terminal app

Prefer the terminal? Install Strata, then run **`strata launch`**.

<details open>
<summary><b>Install commands</b></summary>

**Linux / Mac**

```sh
curl -fsSL https://github.com/Niko1221/Strata/releases/latest/download/install.sh -o install.sh && sh install.sh
```

**Windows PowerShell**

```powershell
irm https://github.com/Niko1221/Strata/releases/latest/download/install.ps1 | iex
```

On Windows, open a new terminal afterwards. Then:

```sh
strata launch
```

Follow the prompts to download and start a model. [Terminal guide](docs/TERMINAL_LAUNCH.md).

</details>
