<h3 align="center">Strata on Windows on ARM</h3>
<p align="center">Chat, code and work with images, locally — on a Snapdragon X laptop.</p>

<p align="center"><sub><b>English</b> · <a href="README.zh-CN.md">简体中文</a></sub></p>

**What this is.** A port of [Strata](https://github.com/Niko1221/Strata) to Windows on ARM (ARM64). Strata's own engine is
replaced by llama.cpp's Vulkan back end, which speaks the same `--serve` line protocol, so the desktop app, its host
server, Control and the Terminal are unchanged in how they drive it. The front end keeps two languages: **Simplified
Chinese and English**.

**What it runs on.** The Adreno GPU through Vulkan; OpenCL is built too and selectable (`--gpu opencl`), and
[port/docs/ADRENO.md](port/docs/ADRENO.md) has the numbers for why Vulkan is the default. The Hexagon NPU is found and
reported, and the engine opens no DSP session: placement of the output head hung the DSP on both packs here (the first
decode never returns), so it is refused unless `STRATA_VK_NPU_FORCE=1`.
[port/docs/features/NPU-FEASIBILITY.md](port/docs/features/NPU-FEASIBILITY.md) has that record, the earlier measurements and the FastRPC
behaviour that used to make the NPU look broken; [port/docs/features/HYBRID.md](port/docs/features/HYBRID.md) is what CPU, GPU and NPU are
each worth on a token, measured.

## Build it

[BUILD-WOA.md](BUILD-WOA.md) has the whole chain: fetch llama.cpp, build the engine, package the engine component, stage
the app resources, build the installer. In short:

```powershell
# the engine: pinned upstream llama.cpp with the port's overlay, then a build (add nothing for a GPU+NPU build)
powershell -NoProfile -ExecutionPolicy Bypass -File port/tools/fetch-llama.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File port/tools/build-engine.ps1

# the app: package the engine component, stage the ARM64 runtimes, build the installer
python port/tools/package_component.py --verify
powershell -File port/packaging/stage-app.ps1 `
    -NodeDir C:\Users\Fuxfantx\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node `
    -PythonDir C:\Users\Fuxfantx\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python `
    -SitePackages strata_control\wheels
npm --prefix apps/desktop run build
```

Prerequisites: the Visual Studio 18 ARM64 C++ toolset, the Vulkan SDK's **ARM64** import library, and three ARM64
runtimes that are not in this repository (Node 24, CPython 3.15, Control's wheels).

## What is in the tree

| Path | What it is |
| --- | --- |
| `apps/` | the desktop app (Tauri shell) and its host server |
| `serve/`, `strata_control/`, `strata_cli/`, `data/` | Strata Control, the Terminal clients and the model catalogue |
| `port/engine/` | the engine component: options, devices, load/generate, the line protocol |
| `port/llama-overlay-vanilla/` | the 36 files this port changes or adds to vanilla llama.cpp |
| `port/tools/`, `port/packaging/` | fetch, build, component packaging, resource staging, `bench.py` (interleaved A/B), `gguf_types.py` (tensor-type histogram) |
| `port/probe/` | `mm-probe`: one `mul_mat` shape on one backend, timed in isolation - the instrument behind every kernel number (`--chain`, `--handoff`, `--ops`) |
| `port/docs/` | the port's own notes: the quickstart, the maintainer rules, the Adreno measurements, the NPU, the CPU+GPU+NPU hybrid analysis, the overlay |

Three of the trees above are **upstream Strata's own surfaces**, kept because the source-mode app and Control drive them:
`setup.py` (its installer), `strata_cli/` + `strata_control/` (its launcher and control panel), `serve/` (its own engine
server) and `data/` (its catalogue). They describe the released NVIDIA/AMD engine, not this port: `setup.py` stops on this
machine at "no NVIDIA GPU found", and the Python-side tokeniser it reaches for lives in a `tools/` package this port does
not ship. The install path here is [BUILD-WOA.md](BUILD-WOA.md) and the app's own engine component.

## Measured on this machine

Snapdragon X2 Elite Extreme (X2E94100), Adreno X2-90, 47.6 GB LPDDR5X shared with the GPU, Windows 11 ARM64.
`port/tools/bench.py` (interleaved rounds, medians) against the models in `C:\Users\Fuxfantx\C-Res\Qwen`:

| model | quant | prompt 512 tok/s | decode tok/s |
| --- | --- | --- | --- |
| tiny-qwen 0.5 B (qwen2) | q5_0/q8_0/q6_K/q4_K | **2 818** | **122** |
| Qwen3.8-27B-Q4 (qwen35) | q4_0 x489 | **74** | 7.0-7.4 * |
| Qwen3.6-35B-A3B (MoE) | q4_0 x431 | **146** | 36.0 |
| Gyro-M 62 GB (qwen4exp MoE) | q8_0 + tq2_t experts | 21 | 6.6-8.7 |

\* decode on a 15.5 GB pack read through mmap drifts with the page cache on a 47.6 GB machine; the two figures are the
same binary on different cache states. Prompt processing, which reads the weights once, reproduces to a few percent.

The prompt column is where this port changed most: the backend's fp16 shader variants cost the int-dot matmul a factor of
four on this driver, so the engine reads the model's tensor table and turns them off for a dense model (see
`port/docs/ADRENO.md`). Gyro-M decode is 6.6-8.7 tok/s and has not moved; what changed is everything around it.
