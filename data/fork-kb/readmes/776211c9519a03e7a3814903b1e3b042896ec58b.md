# Strata CacheKV

**複数エージェントが交代で使う長い会話をSSDへ退避し、Prefillの待ち時間を短縮するStrataのForkです。**

[使い方](docs/DISK_KV_CACHE_FORK.ja.md) · [English guide](docs/DISK_KV_CACHE_FORK.md) · [上流のStrata](https://github.com/Niko1221/Strata)

Strataでメインエージェントとサブエージェントを交代で動かすと、以前の長い会話へ戻るたびに入力を再計算し、Prefillが待ち時間のボトルネックになることがあります。

このForkでは、**RAMを先に使い、容量が足りなくなったら60,000トークンを超えた会話のKVキャッシュと実行状態をSSDへ退避**できます。同じ入力や保存済みの会話と先頭部分が一致する入力が来たときに復元し、一致する部分のPrefillを再利用します。

再起動後も残したい場合は、**`--conversation-cache-persist`** を追加します。RAM対象の会話を回答完了時にディスクにも保存し、RAMに収まらない会話と容量を共有します。短い会話も保存対象にでき、復元はRAMを優先します。[保存タイミング・設定・注意点](docs/DISK_KV_CACHE_FORK.ja.md#再起動後も再利用する任意)をご覧ください。通常エンジンのLinux向け機能で、既定では無効です。

## 実測ベンチマーク

62,074トークンの合成入力で、**初回Prefill約36.2秒 → 会話の復元後は約2.5〜4.2秒**になりました。

| ケース | 再利用したトークン | Prefill時間 |
| --- | ---: | ---: |
| 変更前のStrata：初回入力 | 0 | 36.19秒 |
| このFork：機能オフで初回入力 | 0 | 36.04秒 |
| このFork：機能オンで初回入力 | 0 | 36.55秒 |
| 長い会話A → 短い別会話 → Aへ復帰 | 62,067 | **2.53秒** |
| 長い会話A → 長い会話B → Aへ復帰 | 62,067 | **4.15秒** |

**Aの回答は、すべて変更前のStrataと一致しました。** 保存ファイルを意図的に壊した試験でも、破損を検出して再計算へ戻り、同じ回答を返すことを確認しています。

## サブエージェントを使う場面に

DeepSeek Harnessなどで、**メインエージェントとサブエージェントが同じStrataサーバーを交代で利用する構成**を想定しています。サブエージェントの処理後に長いメイン会話へ戻る際、保存済みの入力と一致する部分を復元できれば、Prefillの再計算を減らせます。

Harnessそのものとの結合試験は未実施です。今回確認したのは、長い会話A・別会話・Aへの復帰という交代パターンです。

## 保存先についての重要な注意

**Optane Memory、または消耗・故障を許容できるキャッシュ専用SSDでの使用を強く推奨します。**

この機能は、会話の切り替え時に大きな状態をディスクへ書き込みます。今回の約62kトークンの会話では、1回の退避で**約1.0 GB**を書き込みました。切り替えを繰り返すと、累積の書き込み量も大きくなります。

- 大切なデータやOSを保存しているSSDと分け、キャッシュ専用の保存先を用意してください。
- **保存容量の上限12 GiBは、累積書き込み量の上限ではありません。**
- OptaneでのKV復元動作は0.2.12で確認しました。長期耐久性や厳密な性能比較は未検証です。

## 使い方と初期設定

**追加したディスクキャッシュは初期状態でオフです。** RAM会話キャッシュは上流の自動設定を維持します。 このForkをソースからビルドし、保存先を指定して有効化してください。上流のインストーラーや配布バイナリには、この追加機能は含まれません。

| 項目 | 初期値・対応範囲 |
| --- | --- |
| 保存対象 | ディスクは60,001トークン以上。生成済みのトークンも含む |
| 配置方針 | RAM優先。上限に達すると古いRAM会話をディスクへ退避 |
| ディスク容量 | 合計12 GiB。足りなくなったら最後の利用時刻が古いものから削除 |
| 保存期間 | 既定は一時保存。`--conversation-cache-persist` で再起動後も再利用 |
| 対応 | Linuxでの逐次処理、layer split、MTP |
| 対象外 | `--batch`、`--peer-device` |

復元ではトークン列・画像情報・実行設定を検証します。KV全体をRAMへ複製せず、小分けに読み書きし、既存のRAM保護も維持します。

[ビルド・有効化・無効化の手順はこちら](docs/DISK_KV_CACHE_FORK.ja.md)。CUDA以外のバックエンドは、このForkでは未検証です。

## Ngram（PLE）のディスクキャッシュ

Ngramテーブルから読んだページを、**複数のドライブへ分散して一時保存**する機能も追加しました。
既存のRAM行キャッシュと併用でき、保存先ごとに容量を指定できます。初期状態はOFF、Linuxの直接I/O向けです。
会話KVキャッシュとは別の機能で、上のPrefillベンチマークはNgramキャッシュの測定ではありません。

[設定・制約・テスト方法](docs/PLE_DISK_CACHE.ja.md) · [English guide](docs/PLE_DISK_CACHE.md)
