# Strata-Kaggle

Run this Strata fork's Qwen3.8 Flash Next inference engine on a Kaggle
notebook with two T4 GPUs. Pi or OpenCode runs on your computer and executes its
file and command tools there; Kaggle only runs inference.

Start with [kaggle_strata_server.ipynb](kaggle_strata_server.ipynb). It downloads
**one selected model**, IQ2_XS by default. Set `MODEL = "coder"` for the pruned
Coder variant or `MODEL = "q2"` for Q2_0. IQ2_XS and Q2_0 retain all 512 experts
per layer. Both shards of the selected model are required.

This fork adds notebook setup, client examples and diagnostics. It uses Strata's
existing model loader, CUDA kernels, multi-GPU implementation and HTTP server.
The upstream engine and defaults are unchanged. See the
[upstream README](README.upstream.md), [engine details](docs/DETAILS.md), and
[multi-GPU documentation](docs/MULTI_GPU.md).

## Validation status

Coder loaded and passed authenticated chat, SSE, structured tool calling and a
tool-result follow-up on Kaggle's two Tesla T4s. Each GPU reported 15,360 MiB;
the container had a 30 GiB RAM limit and four CPUs. The pinned engine built with
CUDA 12.8.93 and GCC 13.3. Nine short responses measured 22.7–30.2 generated
tokens/s at 177, 561 and 2,097 prompt tokens. These are short synthetic runs,
not sustained agent throughput. See the [measurements and raw reports](bench/results/2026-10-17-kaggle-t4-coder/README.md).
The benchmark saves completed measurements even if a later request fails.

Account-free HTTPS inference passed three complete local coding tasks.
Pi v1.3.0 and OpenCode v2.0.28 each read a local file, edited it, ran its test
command and reported success using Coder on Kaggle. No other account was used.
These are short task checks; long sessions and larger contexts remain untested.

Local tests exercise Strata's real HTTP adapter with its mock engine, including
authentication, streamed tool arguments and a tool-result follow-up. These tests
establish adapter behavior, not model quality. See [compatibility notes](docs/KAGGLE.md).
Q2_0 also passed the Kaggle API benchmark. On the two larger synthetic prompts,
generation averaged 32–33 tokens/s versus Coder's 28–29, with slightly slower
prompt processing. Its peak server RSS was 21.72 GiB versus Coder's 9.56 GiB.
See the [Q2_0 comparison and raw reports](bench/results/2026-10-17-kaggle-t4-q2/README.md).

IQ2_XS passed the same Kaggle API/tool checks and is the default. Generation
averaged 26.6, 30.1 and 29.2 tokens/s at the three prompt sizes, about 7–10%
slower than Q2_0. Peak sampled server RSS was 21.62 GiB and container memory
28.16 GiB of its 30 GiB limit. Quality and long agent sessions were not compared.
See the [three-model comparison and IQ2_XS reports](bench/results/2026-10-17-kaggle-t4-iq2-xs/README.md).

## Run the notebook

1. Import the notebook, or push it using the Kaggle CLI below.
2. Select **GPU T4 ×2**, **Internet on**, and
   **Session options → Persistence → Files only**. The public CLI cannot set the
   editor's persistence switch; enable it in the editor.
3. Keep `MODEL = "iq2_xs"` initially. Set paths, context and ports in cell 1.
4. Run the eight sections in order. The default run verifies the localhost API,
   benchmarks it and stops. Results go to `/kaggle/working/strata-results`.

Setup builds the pinned fork for compute capability 7.5, reusing its virtual
environment and build directory on reruns. It uses the image's CUDA compiler
and does not install drivers. Missing tools and build failures are visible.
To reuse a separately saved engine, set `PREBUILT_ENGINE` to its path and
`PREBUILT_SHA256` to its independently recorded SHA-256. It must come from the
same revision and build for sm_75. The notebook checks it before copying it.

The initial configuration splits layers 0–23 onto GPU 0 and 24–47 onto GPU 1,
trims each stage's dense weights, and uses resident CPU experts, a 1,024-token
prefill chunk, 8,192-token context, q4_0 KV and `--spec 2` (required for native
packs, including runs without MTP). Its native GGUF pack avoids a second
copy of all routed experts in `experts.bin`. The MTP draft model is omitted to limit downloads
and memory. These settings are a starting point, not a measured speed optimum.

## Disk persistence

`PERSISTENT_DISK = True` is the default. Build files, virtual environment, pack
metadata and tokenizer live in `/kaggle/working/strata-cache`. Enable Kaggle's
**Files only** setting too; a Python variable cannot change that platform setting.

Coder is 58,408,584,928 bytes, Q2_0 is 66,423,878,624 bytes and IQ2_XS is
68,026,093,024 bytes. None fits the 20 GB working disk documented by Kaggle and
observed in the first run. Weights
therefore download to `/kaggle/temp/strata-models` by default. That path is
**ephemeral**, even with Files only enabled. Disk capacity is checked before
building or downloading.

For durable weights, create a Kaggle dataset containing the two selected GGUF
shards and attach it through **Add Input**. Matching files under `/kaggle/input`
are found automatically. You can also set `MODEL_DIR` to their directory. They
are read in place. Kaggle's dataset UI supports hosted-file imports; use the
pinned Hugging Face URLs described in `MODELS` in `kaggle_runtime.py`, or upload
files you already have. Check your account's dataset storage limits first.

On a larger persistent volume, set `MODEL_DOWNLOAD_DIR` to a path on that volume.
Changing `MODEL` downloads only the new selection. Previously cached files stay
in place; switching variants can require space for both until you remove one.
Every selected shard is checked against pinned byte sizes and SHA-256 hashes.
Downloads resume from `.part` files, and ignored resume ranges are rejected.

## Kaggle CLI and credentials

The Kaggle CLI is an optional local operator tool, not an inference dependency:

```bash
python -m venv .venv-kaggle
. .venv-kaggle/bin/activate
python -m pip install kaggle==2.2.4
read -rsp 'Kaggle token: ' KAGGLE_API_TOKEN; printf '\n'
export KAGGLE_API_TOKEN
python connect.py -- python agent_smoke.py
```

Install the managed client commands once:

```bash
python connect.py --install-launchers
```

Then run `strata-opencode -- /path/to/project`, or run `strata-pi` from your
project directory. For a fresh terminal, the launcher also accepts Kaggle's
standard `~/.kaggle/access_token` file. Keep this file outside the checkout and
readable only by your user (mode 0600). `KAGGLE_API_TOKEN` takes precedence when
you rotate the token. Both commands are installed in `~/.local/bin`. They reuse
an active notebook or start one, discover its actual model through `/v1/models`,
and register **Strata (Kaggle)** in both clients' normal model selectors.
OpenCode starts with a private server so it reads the current connection.
The launcher temporarily merges its provider into your existing JSON settings;
other providers remain available. On confirmed shutdown it restores the previous
provider and default model, preserving unrelated settings changed in the meantime.

Closing the managed client cancels the recorded Kaggle session and waits for
Kaggle to acknowledge it. Terminal closure and client failures also trigger
cleanup. Use these commands for automatic shutdown; an independently launched
plain `opencode` or `pi` process is not owned by the launcher.

```bash
strata-opencode --attach -- /path/to/project  # require an already running notebook
strata-pi --idle-seconds 600                  # ten idle minutes for a new notebook
python connect.py --stop                     # stop the recorded session explicitly
```

The default idle timeout is **15 minutes**. This leaves room for editing and
local tool commands between requests; use `--idle-seconds 0` to disable it.
The notebook's own timer checks `/v1/status`: active or queued inference requests
reset it, as do completed requests between checks. It runs after startup and
the optional benchmark. `--seconds` remains a separate hard session-serving
limit, 30 minutes by default. Timeout settings are chosen when launching a new
notebook; attaching reuses its existing settings. After idle shutdown, exit and
relaunch the client when you need the model again. `--keep-running` disables
cancellation on client exit, while the notebook's own timers still apply.

The official Kaggle CLI does not expose session cancellation. The small
`kaggle_session.py` command uses its bundled SDK's `CancelKernelSession` method.
The notebook reports its runtime session ID with a per-launch nonce; the launcher
never substitutes the notebook's version number for that ID. A cancellation
request alone is not reported as shutdown: it waits for a terminal status and
checks that the notebook version has not changed. If it cannot confirm stopping,
it reports the error and retains the session record for `--stop` or manual cleanup.
The runtime ID arrives when the first notebook cell runs. If startup is
interrupted while Kaggle still queues the job, stopping it may require Kaggle's
**Active Events** window; the public status API does not provide that ID.

This launches the private GPU notebook, waits for its temporary HTTPS endpoint,
and runs the file-and-command smoke test on your computer. It needs **only a
Kaggle account**: no Cloudflare/ngrok account, domain or tunnel token. Use
`--model coder` or `--model q2` to select an alternative, `--seconds 1800` to bound serving, and `--kernel
your-name/strata-kaggle-coder-server` for another owner. `--model-dataset
owner/dataset` attaches durable weights. The default builds the engine; an
existing compiled cache can be supplied with `--engine-dataset owner/dataset`
and its independently recorded `--engine-sha256`. To prepare durable model
weights without spending GPU quota, see the cold-start section below.

The notebook generates a separate inference key in memory. The launcher sends
only a public RSA key to Kaggle; the notebook returns the inference key encrypted
with RSA-OAEP/SHA-256. The private key and `connection.env` stay under
`~/.cache/strata-kaggle`, with private files readable only by your user. OpenSSL
and OpenSSH are used; no Python cryptography package is needed. No credential
is embedded in notebook source or printed in logs. During inference launches,
`KAGGLE_API_TOKEN` stays on your computer and is removed from the agent's environment.

Load the connection into your shell without displaying the key:

```bash
. ~/.cache/strata-kaggle/connection.env
python benchmark.py --base-url "$STRATA_BASE_URL"
```

For a manual notebook-only benchmark, the underlying CLI remains available:

```bash
kaggle kernels push -p . --accelerator NvidiaTeslaT4 --timeout 7200
kaggle kernels status ninnix/strata-kaggle-coder-server
kaggle kernels logs ninnix/strata-kaggle-coder-server
kaggle kernels output ninnix/strata-kaggle-coder-server -p strata-results
```

Change the owner in `kernel-metadata.json` for another account. The kernel is
private with no attached datasets by default. Add your model dataset to
`dataset_sources` when available. Local environment variables are not copied
into a notebook by `kernels push`. A batch run ends after its final cell.

## Cold starts and GPU quota

Kaggle accounts for **allocated GPU-session time**, including setup, downloads,
model loading and idle time. Zero GPU utilization or unloading the engine does
not stop that clock. Only ending the GPU session saves its remaining time.
See [Kaggle's GPU usage guidance](https://www.kaggle.com/docs/efficient-gpu-usage).
There is no inference-only GPU-hour accounting on this notebook platform.

The measured IQ2_XS startup was 18 minutes 17 seconds with a cached engine:
14 minutes downloading/verifying weights and 3 minutes 50 seconds starting the
loaded server. Preparing the model as a dataset removes repeated network
downloads; verification, pack preparation, allocation and loading remain.
Seconds-level cold starts have not been demonstrated for this model.

Prepare the selected model once on a **CPU-only Kaggle worker**:

```bash
python prepare_cache.py --dataset your-name/strata-kaggle-iq2-xs-weights \
  --engine-dataset your-name/strata-kaggle-sm75-engine \
  --engine-sha256 YOUR_VERIFIED_ENGINE_SHA256
```

The engine arguments are optional. The worker downloads only the two selected
model shards, checks their pinned hashes and uploads a private dataset. This
uses your dataset storage and CPU notebook allowance, with no GPU allocation.
The worker uses Kaggle's injected notebook API credentials for upload. Your
`KAGGLE_API_TOKEN` remains on your computer; no key or secret attachment is
needed in the cache notebook. The monitor follows dataset status through the
Kaggle API and retries temporary status failures without restarting downloads.
The worker is stopped after completion. Cache preparation needs no tunnel.
The one-time download and upload can take over an hour. Follow transfer progress
with `kaggle kernels logs -f your-name/strata-kaggle-model-cache-cpu`.

The launcher saves dataset choices in `~/.cache/strata-kaggle/defaults.json` and
attaches them automatically on later starts. Interactive launches skip the full
benchmark suite; use `python benchmark.py` explicitly when measuring speed.
Dataset availability and your account's storage limits must permit the cache.

Keep the Kaggle credential in `KAGGLE_API_TOKEN`; the inference notebook does
not need it. For manual remote setup without the launcher, generate a separate
`STRATA_API_KEY` of at least 24 characters and attach it using Kaggle
**Add-ons → Secrets**. Use that key in your local environment too.
The notebook checks environment variables first, then attached secrets, following
[qwen-ple-transfer](https://github.com/Ninnix/qwen-ple-transfer).

## Account-free HTTPS tunnel

Kaggle's [AUP](https://www.kaggle.com/aup) prohibits resource abuse, including
server farming and activity unrelated to ML data science. Its published rules
do not establish permission for persistent remote coding-inference services.
Confirm your intended use is permitted before enabling remote access. The
notebook-only benchmark is the default testing alternative.

The launcher configures [localhost.run](https://localhost.run/docs/) using
`nokey@localhost.run`. It requires no account or SSH key. For a manual launch
with an attached `STRATA_API_KEY`, set:

```python
TUNNEL = "localhost.run"
REMOTE_ACCESS_PERMITTED = True
SERVE_SECONDS = 1800
```

Strata binds to localhost and SSH makes an outbound encrypted connection.
The service assigns an HTTPS hostname automatically. The notebook verifies
authentication and runs streaming/tool tests through it. SSH uses its own known
hosts file and accepts a host key on first connection; later changes are rejected.
The client ignores personal SSH configs, keys and agents. No tunnel credential
is required. Free hostnames change and the service limits bandwidth; no uptime
or stable hostname is promised. Cloudflare Quick Tunnels are unsuitable here
because [they do not support SSE](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Interrupt the last cell to stop the tunnel and server, or let `SERVE_SECONDS`
expire. Kaggle can end the session sooner. No activity simulation, automatic
session restarts or quota workarounds are used. The tunnel does not keep the
GPU session alive.

## Pi and OpenCode on your computer

```bash
. ~/.cache/strata-kaggle/connection.env
python benchmark.py --base-url "$STRATA_BASE_URL"
python agent_smoke.py --base-url "$STRATA_BASE_URL"
```

The smoke test asks the model to read a temporary local `answer.py`, change its
return value from 41 to 42, and run a local assertion. It checks that all three
tools completed. Generated Python executes locally with your user permissions;
use a disposable environment for an untrusted model.

The managed launcher configures both clients automatically. For manual setup, merge
[pi-config-example.json](pi-config-example.json) into
`~/.pi/agent/models.json`, replace its example hostname with `$STRATA_BASE_URL`'s
current value (Pi's `baseUrl` is a literal URL), then run:

```bash
pi --provider strata-kaggle --model strata-iq2_xs
```

For OpenCode, merge [opencode-config-example.json](opencode-config-example.json)
into `opencode.json` (v2 format, checked against the installed v2.0.28 client), then run:

```bash
opencode --standalone
```

`--standalone` starts a private server with the current endpoint and key from
your environment. An already running background service keeps its earlier
environment until restarted.

Both examples advertise 8K context and at most 2,048 output tokens. Update the
limits when changing `CONTEXT`, leaving room for prompt, tools and reasoning.
For Coder, use model ID `strata-coder`; for Q2, use `strata-q2` in the examples
and benchmark commands. Verify
actual client sessions and long tool trajectories before relying on them.

## Benchmark and tests

`benchmark.py` uses only the standard library. It checks `/v1/models`, ordinary
chat, SSE termination, finish reasons, structured tool arguments and a tool-result
follow-up. Each run records TTFT, elapsed time, server token counts and engine
prompt/decode rates. Missing rates stay `null`; SSE chunks are never counted as
tokens. Memory samples include available system RAM, the server process tree's
RSS when its PID is supplied, and memory per GPU.
The report also records cgroup memory use, peak and limit where available.
Completed runs and error details are saved even if a later request fails.

```bash
python benchmark.py --words 128 512 2048 --repeats 3
python agent_smoke.py --repeats 10 --output agent-results.json
```

Prompt sizes above are **words**, not context lengths. Compare returned
`prompt_tokens`. To test longer context, raise `CONTEXT`, restart the server,
update client limits, and repeat. Startup records separate build/install,
download/verification, pack creation and server start-to-ready time. The latter
includes tokenization setup and model loading; it is not engine-only load time.
`--repeats` runs complete local coding tasks; `--rounds` only limits the turns
allowed for one task and does not extend a successful task.

The notebook is generated from reviewable Python source:

```bash
python tools/build_kaggle_notebook.py
python tools/build_kaggle_notebook.py --check
python tools/test_kaggle.py
```

Install Strata's existing `jinja2` and `regex` dependencies to include the real
HTTP adapter test. No engine sources were changed. The notebook builds its CUDA
target on the actual T4 image; HIP and SYCL behavior is unchanged.
