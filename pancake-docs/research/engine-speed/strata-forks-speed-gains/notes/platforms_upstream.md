# Other-platform / other-model Strata forks + upstream after v0.2.13: platform-independent speed ideas for pancake (state 2026-11-10)

Scope: dennis-akimov/Strata (Apple Silicon), Emefedez/strata-asahi (Vulkan on Asahi), NeneNyann/Strata-intel-sycl-windows (Intel Arc SYCL), isichan-ai/Strata-GLM (GLM-5.3-Flash on RTX 5090 + RAM + NVMe), and upstream Niko1221/Strata after v0.2.13 (2026-11-09). Target box: RX 7900 XT 20 GB (HIP gfx1100), Ryzen 7 5700G (AVX2, 8C/16T, PCIe 3.0), 57 GB RAM, single user, Qwen3.8-Flash-Next 125B MoE IQ2_XS. Our fork: /home/dan/clone-of-d/src/Strata, branch port/rdna3-decode (219 commits on top of upstream 146df3c4 = v0.2.12).

Status labels: NEW = not in our tree or MOD_PLAN; ALREADY-HAVE = code or result already in our fork; REJECTED-BEFORE = in MOD_PLAN's closed/not-adopted register or measured negative here; KNOWN = already listed as an untested idea. All four forks are standalone repos (GitHub `fork: false`), so the GitHub compare API against upstream returns 404; the diff contents below come from READMEs and commit logs, not from line diffs.

## Q1. What each fork changes, its numbers (author-measured), last commit, and what transfers to HIP + CPU offload

### Takeaway
Only isichan-ai/Strata-GLM has offload-bound work that matters for our box: a CPU-pool tail scheduler, an async VRAM-tier swap (we already have it), NT-store host copies on the prompt path, a two-drive expert-file mirror, weight-based miss-skip, and a list of measured negatives that match our own rejections. The Apple, Asahi and SYCL forks are mostly backend ports. Two ideas from them are platform-independent: a cost-gated MTP verify (`--spec-sched cost`) and grouped (layer-major) prompt chunks. We already have both in some form.

### Cited Findings

**isichan-ai/Strata-GLM** (37 stars, last commit 2026-10-13 `6feb85fed`, base Strata v0.1.41, CUDA/Windows)
- Hardware: RTX 5090 32 GB, Core Ultra 9 285K, 128 GB DDR5-4400 (2 channels), NVMe, Win 11. GLM-5.3-Flash UD-IQ4_XS (157 GB). Author-measured: **31.3 tok/s short chat** (median of 3, best 32.6), **580 tok/s** reading a 4,400-token prompt. llama.cpp on the same PC: 7-10 tok/s decode, 42-55 tok/s prompt — [README](https://github.com/isichan-ai/Strata-GLM)
- **CPU single-token fix:** a one-token window's CPU experts went to ggml's per-token dot instead of the AVX2/AVX-VNNI row kernels, because of a `max()` with the 2-token default. After the fix an IQ3_S gate/up expert ran 2.0x faster on a P-core. Gate and up rows now run in one loop (bit-identical) — [README, update 2026-10-11](https://github.com/isichan-ai/Strata-GLM)
- **Pool tail scheduling:** `STRATA_POOL_GUIDED=1` cuts row ranges smaller toward the end of a phase. `STRATA_POOL_ETAIL=6` gives a phase's last 6 tasks to P-cores. Neither changes a bit. Together with the fix above: short chat 29.6 → 31.3 tok/s, follow-up 23.1 → 24.2 — [README](https://github.com/isichan-ai/Strata-GLM)
- **`--adapt-async 1`:** VRAM-tier expert swaps run on their own thread while the next windows compute, instead of between windows (3.5-4.5 ms a window). Short chat 24.9-26.0 → 28.7-30.1 tok/s; after a 4,228-token summary 15-16 → 20.6 — [README](https://github.com/isichan-ai/Strata-GLM)
- **Prompt-path host copies:** the prompt was limited by RAM bandwidth. A DMA from page-locked RAM made 46.6 GB/s alone but 17.0 GB/s next to 4 memcpy threads. Blob copies now use non-temporal stores (`STRATA_NT_COPY`) and the fetcher threads are kept across launches (`STRATA_GLM5_PF_CREW`). 4,829 tokens: 8.3-8.7 → 7.5-7.6 s; decode unchanged — [README, update 2026-10-14](https://github.com/isichan-ai/Strata-GLM)
- **Two-drive expert mirror:** `STRATA_MIRROR_DIR` holds a copy of the shards on a second drive, and `STRATA_MIRROR_SHARE` splits the reads (4.0 + 6.9 = 10.9 GB/s). Start 66 → 43 s, short prompt 4.1 → 2.4 s, decode +15% after a 360-token follow-up and +25% after a 7,910-token prompt (80 GiB RAM tier, the rest on SSD) — [README](https://github.com/isichan-ai/Strata-GLM)
- **Unmapping GGUF shards once the file tier reads unbuffered** (upstream 52a2dd10): on NTFS a mapped shard serialises unbuffered reads. 892-token prompt 9.4 → 7.9 s, decode about 10% faster — [README](https://github.com/isichan-ai/Strata-GLM)
- **Layer-walk prefill:** each layer's routed experts are streamed into VRAM once per group of up to 16K tokens instead of once per 4K chunk, then multiplied with int8 MMQ. The SSD tier is prefetched one layer ahead. 4,400 tokens: 59.8 → 7.4 s — [README](https://github.com/isichan-ai/Strata-GLM)
- **Expert skipping** (`STRATA_GLM5_SKIP_KEEP=2 SKIP_MINW=0.10`): an expert under 10% of the token's routing weight that is not in VRAM is skipped (the top 2 always run). 20 → 25 tok/s (+30% est.), next-token KL 0.016-0.022 against a 0.013 run-to-run floor. About 1 token in 100 changes on long reasoning — [README](https://github.com/isichan-ai/Strata-GLM)
- **Measured and not adopted by isichan:** `--pcie-frac` (DMA and CPU share the RAM bus); MTP drafting (the CPU's expert work grows with the window); a layer-ahead router prediction for SSD reads (wrong reads cost more than they hide); renormalising skipped weight; few-expert self-speculation (slower even with a perfect drafter) — [README](https://github.com/isichan-ai/Strata-GLM)
- **Where a 50 ms token goes on their box:** CPU RAM-resident experts 19-25 ms (the pool reads 44 of 60 GB/s), about 2,000 small GPU kernel launches 13 ms, SSD 3 ms — [README](https://github.com/isichan-ai/Strata-GLM)
- **Correctness:** MMQ reads past the end of matrices whose rows are not a multiple of 256, which gave random "!!!!" answers. Fix: MMQ only when the row length % 256 == 0. Prompt-state slot files are now tied to the build. State resets run on the compute stream. NaN guard per window — [README, update 2026-10-13](https://github.com/isichan-ai/Strata-GLM)

**Emefedez/strata-asahi** (0 stars, last commit 2026-10-25 `53381404d`, branch `vulkan-asahi`)
- A Vulkan runtime that implements Metal's `mtl_rt.h`, with kernels rewritten in Slang. Author-measured on an M1 Max 32 GB, Q2_0, experts streamed from SSD, 8 GB arena: 12.9 tok/s story / 9.5 code without drafts; 13.3 / 11.5 tok/s with `--spec 8 --suffix-draft 3 --mtp --mtp-max-t 2 --spec-sched cost` — [vulkan/README.md](https://github.com/Emefedez/strata-asahi/blob/vulkan-asahi/vulkan/README.md)
- **`--spec-sched cost`** (in `src/spec/draft_policy.cpp`): verifies an MTP draft only when the calibrated chance of acceptance pays for the measured cost of the wider window. The README credits DeepSeek's DeepInfer for the idea — [vulkan/README.md](https://github.com/Emefedez/strata-asahi/blob/vulkan-asahi/vulkan/README.md)
- **Chunked prompt path:** 14.7 tok/s through decode windows vs 123.8 tok/s at chunk 2048 (8.4x) and 134.7 at 4096 (9.2x), same greedy answer — [vulkan/README.md](https://github.com/Emefedez/strata-asahi/blob/vulkan-asahi/vulkan/README.md)
- **Grouped prompt chunks, layer by layer:** each layer's streamed experts are read once per group. 3.3x fewer storage reads, same answer, but only about 1.5% faster because the per-chunk cost is GPU work. A merged expert-pass variant `STRATA_METAL_PROMPT_MERGE=1` was not yet run — [commits 10857b45e / e2e752fb4 / 53381404d](https://github.com/Emefedez/strata-asahi/commits/vulkan-asahi)
- **`STRATA_VK_SPIN=1`:** the whole window goes in one command buffer and the GPU spins on a host flag at each cut. About 6 µs per cut instead of 85-115 µs, but it froze the desktop once — [vulkan/README.md](https://github.com/Emefedez/strata-asahi/blob/vulkan-asahi/vulkan/README.md)
- **Balanced chunks:** buffers get 1/32 more rows so a prompt splits evenly over the fewest passes — [commit ff1a0aa79](https://github.com/Emefedez/strata-asahi/commits/vulkan-asahi)

### Inferences
- The isichan negatives match our register independently: `--pcie-frac` loses when DMA and CPU share DDR (we found `--pcie-frac 0` best on the 7900 XT), layer-ahead prefetch does not pay (our "MoE-SpeQ / SP-MoE as prefetch [closed]"), self-speculation is slower. This supports keeping those items closed.
- isichan's time breakdown (CPU experts bandwidth-bound at about 73% of DDR peak, plus about 2,000 launches = 13 ms) is the same shape as our edit window (CPU experts 17.4 ms + GPU-reach wait 15.75 ms in MOD_PLAN). That makes the pool-tail scheduler the only cheap new CPU-side lever. Expected gain is low single digits (their +6% included the 2x kernel fix we do not need).
- MTP behaves differently on the two boxes: isichan drops MTP because CPU work grows with the window; we keep it because most experts sit in VRAM/the tier. The difference is about the CPU-miss ratio, which our DraftPolicy cost model already prices.

### Gaps
- No line-level diffs were possible: none of the four repos is a GitHub fork of upstream (compare API 404), and cloning them was out of scope for the disk budget.
- I did not verify whether our prompt path does host memcpy into pinned staging (needed to judge NT_COPY). Needs a code read of `src/prefill/prefill.cpp` staging.
- asahi's `STRATA_METAL_PROMPT_MERGE` (merged expert passes) has no measurements ("not yet run").
- NeneNyann's own `docs/SYCL_WINDOWS.md` benchmark detail was not read.

### Inferences
- The XTX community numbers are not like-for-like: IQ3_S vs our IQ2_XS, a 24 GB vs 20 GB card, PCIe 4.0 vs our PCIe 3.0. Still, their prompt-16k of about 2,940-3,030 tok/s is roughly 3x our measured cold prompt rate (5.2K in 6.51 s ≈ 800 tok/s; 41.8K in 42.9 s ≈ 975 tok/s, MOD_PLAN). PCIe 3.0 explains at most about 2x of the expert-streaming cost. A same-config comparison (their flags on our box, a 16K prompt) is a cheap diagnostic, and layer-major prefill (Q1) is the obvious lever to test with it.
- Their decode (77-89 tok/s on 0.1.59 IQ3_S) is below our ~112 tok/s (IQ2_XS), which agrees with the earlier survey's conclusion that our kernel ports lead on decode.
- The XTX user runs the Strata-rdna3 zh60k draft vocab, which our tests found worse (MOD_PLAN "zh60k vocab" in the worse list). This is not a reason to revisit it.
