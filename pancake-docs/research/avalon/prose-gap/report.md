# Pin down Avalon's prose edge before porting

Pancake can close Avalon's prose decode gap, but the gap is small and not yet established, and most of it sits in the cost of each verify window rather than in the draft policy. On the night-queue prose runs Avalon decodes **3.6 to 8.4% faster** than the Pancake preset, and a separate 2026-11-11 run shows **3.4%** ([RESULTS.md](/home/dan/night-queue-run/RESULTS.md), [REPORT.md](/home/dan/clone-of-d/src/Strata/bench/results/2026-11-11-vs-avalon/REPORT.md)). Both sit inside the roughly 5% start-to-start noise. Avalon wins by **about 16% more tokens per window** and loses about **9% more time per window**. Each millisecond of fixed per-window cost is worth about **5% decode**, and each point of draft acceptance about **1%**, so the largest levers are the fixed window cost and draft quality, not Avalon's fixed two-draft policy. Pancake's own data already shows that drafting more is not the answer: the third draft nets roughly -4%. Two confounds must be removed before any port: Avalon's default MoE tail skip is lossy and on by default in its code, and its head was benchmarked on the wrong main model. The Pancake baseline also still carries lossy flags.

## Avalon wins on tokens per window and loses per window

The prose table in the night-queue results gives tokens per window, milliseconds per window and acceptance for each prompt ([RESULTS.md](/home/dan/night-queue-run/RESULTS.md), lines 425-434) **[measured]**. Averaged over story, tips and moe, Pancake commits **1.96 tokens per window at 18.5 ms** and Avalon commits **2.27 tokens per window at 20.1 ms**. That is +16% tokens and +9% time, which nets to the +6% decode gap. Both sides are consistent with their drafting policy: Avalon's accepted-draft rate implies **2.0 drafts per window on every prose prompt** **[derived]**, which matches the code's `--spec-draft-n-max 2` with no confidence cut **[code, notes]**.

Pancake drafts fewer than Avalon on prose. Its accepted-draft rate implies **about 1.65 drafts per window** on average **[derived]**, because the `--spec-min-p 0.5` cut stops the chain early. The min-p policy is therefore already trimming drafts that Avalon sends. Accepted drafts per window are **0.96 for Pancake against 1.27 for Avalon**, a gap of about 0.31 that splits roughly two-thirds from draft count and one-third from per-draft acceptance **[derived]**. Acceptance is 53 to 63% for Pancake and 59 to 67% for Avalon on prose **[measured]**, so the head is only modestly better, about 5 points.

The arms that already exist show what extra drafts buy. Forcing three drafts (`--spec-min-p 0`) reaches 2.16 tokens per window but costs 21.1 ms per window, for -5% decode on story and moe and flat on tips ([RESULTS.md](/home/dan/night-queue-run/RESULTS.md), prose-var-01B) **[measured]**. The one-draft arm (`--spec 2`) runs 16.6 ms per window at 1.65 tokens per window and is -5 to -24% **[measured]**. A linear fit through those two points gives **about 14 ms of fixed cost per window and about 2.2 ms per extra draft** (a row plus a draft decode step) **[derived, two points, unverified linearity]**. The base preset at 1.65 drafts predicts 17.8 ms against 18.5 measured, which is consistent. So the lever is the fixed 14 ms, and the draft count is a secondary lever with a break-even near the second draft.

The earlier MOD_PLAN claims do not survive this table. Phase 17.2 says the two engines have "same acceptance" and that Avalon is "steadier" ([MOD_PLAN.md](/home/dan/clone-of-d/src/Strata/MOD_PLAN.md), line 2446). Acceptance differs by 2 to 9 points per prompt, and in this run Avalon's standard deviation is 2.7 to 4.7 tok/s against 1.1 to 2.7 for the Pancake base series **[measured]**. The same line quotes ranges (Avalon 98 to 111, Pancake 93 to 102 tok/s) that do not match RESULTS.md (Avalon 104 to 116, Pancake 101 to 110). This is **unresolved**: the 17.2 wording should be rewritten from the saved numbers before anyone plans work against it.

## Two confounds sit on Avalon's side, and one on Pancake's

Avalon's MoE tail skip defaults to rank 7 when `GGML_CUDA_MOE_TAIL_SKIP` is unset, and its own comment says it "changes the output" ([moe-cache.cu](/home/dan/clone-of-d/Avalon/ggml/src/ggml-cuda/moe-cache.cu), around line 9677) **[code, rechecked]**. The benchmark script sets no such variable ([matrix.sh](/home/dan/clone-of-d/src/Strata/bench/results/2026-11-11-vs-avalon/raw/matrix.sh), line 36) **[measured]**, so the default applies to the Avalon prose numbers. Pancake's equivalent, `STRATA_ROUTE_TAIL_SKIP`, is a switch whose default depends on the architecture, on the GPU expert-cache fraction (off at 90% or more cached) and on batch size; the source comment reports a KL of about 0.003 to 0.006 against the no-skip output ([generate.cpp](/home/dan/clone-of-d/src/Strata/src/program/generate.cpp), lines 12927 to 12960) **[code, rechecked]**. Whether it is off for this model on gfx1100 was not confirmed here, and the notes say off **[unverified]**. Until Avalon is run with `GGML_CUDA_MOE_TAIL_SKIP=0`, part or all of its prose edge may be a lossy path, not a drafter advantage. That is the first test to run.

The second Avalon-side confound is the head. The night-queue server log shows the **IQ2_XS main model paired with the IQ3_KS hybrid MTP head**, which the head was not quantized for ([srv-prose-avalon.log](/home/dan/night-queue-run/raw/srv-prose-avalon.log), line 8) **[measured]**. Its acceptance in its own pairing is not measured, so the head's true quality relative to Pancake's is **[unverified]** in either direction.

On Pancake's side, the daily preset still sets `STRATA_VERIFY_DEFER_CPU` to `"1"` on the `port/rdna3-decode` branch (`configs/pancake/flashnext-iq2_xs-fast-hip.json`, line 104) **[code, rechecked]**. The owner's decision to remove it is therefore not in this branch's preset as read. The same preset sets `STRATA_GR_RDNA_A8`, `STRATA_GR_RDNA_Q8` and `STRATA_PF_F16=2` (lines 87, 95, 97), which the env table marks lossy; that classification comes from a worktree copy of the table and is **[unverified]** against the main tree. MOD_PLAN reports that turning deferral off cost **about 3% on IQ2_XS**, but calls the result "NOT established" because the runs overlapped with agent load ([MOD_PLAN.md](/home/dan/clone-of-d/src/Strata/MOD_PLAN.md), line 2457) **[measured, unverified]**. Removing deferral from the baseline would therefore probably widen the prose gap by about 3%. Re-measure the baseline after any such change, not before.

## The noise floor decides which gaps are real

Start-to-start variation is the constraint. Per-prompt medians of the same preset in two server starts differ by a standard deviation of about 7 points, roughly **5% per start** on five prompts **[derived, n=5]**. At that noise a 3% effect needs about **45 starts per arm**; at 2.5% it needs about 12 **[derived from the power formula in the notes]**. The Avalon-to-Pancake prose gap of 3.6 to 8.4% therefore cannot be established with the current queue. A 5 to 6% bar is reachable with 12 to 20 starts per arm, so the realistic plan is to state the bar honestly, run the A-A control first, and only then decide the arm count.

The text check is the weakest instrument. [abtest.py](/home/dan/clone-of-d/src/Strata/tools/pancake/abtest.py) compares each arm's first hash only with base's first hash (lines 530 to 542) **[code, from notes]**. Within one server, the base config produced six distinct hashes in six runs on the story prompt **[measured]**, so a "different text" result proves nothing. Every text comparison needs `base_rep` as the reference, and every exactness claim needs a count of mismatches against any base hash, not one.

Owner rules still apply: benchmarks run only at night through the night queue, on a quiet machine, one engine at a time, with outputs and logs on the root disk, not on the D drive ([MOD_PLAN.md](/home/dan/clone-of-d/src/Strata/MOD_PLAN.md), Phase 17) **[memory]**.

## Conclusion

The prose gap is a per-window problem as much as a drafting one. Avalon's advantage comes from **accepting more drafts per window at a slightly higher window cost**, and Pancake's data shows that its own third draft does not pay. The cheapest real gains are therefore a smaller fixed window cost (each millisecond is worth about 5%) and a head that accepts a few points more, not a copy of Avalon's two-draft rule. Pancake's code lead, about 16% over Avalon on the js prompt, also means any draft-policy change must be judged on code as well as prose.

Three things remain open and would change this ranking. First, how much of Avalon's edge is its default tail skip; if most of it is, the honest port is a lossy switch with a quality gate, not an exact change. Second, whether the 14 ms fixed cost is expert-offload waiting, which the profile must show before any draft work. Third, whether Avalon's head is better than Pancake's once it is paired with its own main model. The owner should also decide whether the lossy deferral and GR flags stay in the daily preset, because removing them moves the baseline the gap is measured against.
