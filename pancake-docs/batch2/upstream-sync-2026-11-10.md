## What the range is

Upstream spent these three days on the Qwen4 preparation (a compiled model geometry, `STRATA_GEOMETRY`, for new
shapes; upstream checked that the Flash-Next device code is unchanged by it), the 0.2.13 release (signed-feed model
list, per-shape engine components, app and Control work), a vendored ggml tree with the CMake split by backend, a
config-snapshot test suite and CI portability. There is very little engine bug fixing in it, and no kernel perf work
for our cards: the only "perf" engine commits flip launcher speed switches into engine defaults (CUDA parallel stack,
GDN_TC / GDN_CONVL2, HC_Q8 on UD files, gfx12 chunked GDN, hipBLASLt table on gfx1151 only). Those switches already
exist in our tree as opt-ins, so taking the flips would only change our default path, which the fork policy forbids.

## Risks

- #5327 changes behaviour on an uncapped Linux run that is short of RAM: the arena loads through the file cache
  instead of falling back to `--mmap-experts`. Upstream's review keeps #4051's anonymous-RAM case refused and
  credits only droppable pages; the danger case (a host stalling in reclaim) needs memory the kernel cannot drop,
  which is not credited. Our presets always run capped, where the credit is off. If anything looks wrong:
  `STRATA_ARENA_FILE_CACHE=0`.
- `GGML_NO_BACKTRACE=1` hides ggml's gdb backtrace from engine aborts started through the server; a developer
  debugging a crash sets `STRATA_BACKTRACE=1`.
- No engine build was done (rule 3). The C++ changes are confined to `expert_source.cpp`/`.hpp`,
  `ple_residency.hpp`, `ple_residency_test.cpp`, `generate.cpp` (two lines and a guarded printf) and
  `CMakeLists.txt`; every name they use was checked to exist in our tree (`hm.cgroup_limit`, `pin_by_need_`,
  `pin_pairs_`, `arena_mmap`, `shared_arena_file`, `lay.blob_bytes`, `o.serve`, `<iterator>`/`<sstream>` includes).
